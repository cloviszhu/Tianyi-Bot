# 天意Bot 0.6.10：识别候选接入本机图库

“视觉识别”页现在把 UIA 文字和置信度至少90%的 OCR 文字交给现有指令解析器，列出加图/取图候选。不默认选择、不把历史候选视为新消息。选择后点击处理：取图直接从该群本机图库显示图片；加图需人工确认关键词并选择对应原图，调用现有图库校验、哈希去重和 SQLite 入库，保留源文件。群必须已保存至配置。本次仅实现人工确认的本机流程，不是全自动微信群机器人；自动关联发送者、微信原图下载与群发送仍未接通。OCR 置信度不代表消息身份可信，因此候选不会自动写入图库。

分身 GUI 新增“视觉识别”页。填写配置群后点击“开始截图＋OCR 对比”，以 PrintWindow 获取绑定微信的聊天列表区域，在内存中交给 OpenCV 与 RapidOCR 1.4.4（CPU ONNX）识别，并展示缩略画面、坐标/置信度对应的文字及 UIA 文字。无需云服务或 YOLO，不保存截图或 OCR 正文。聊天页的定位和精确群名校验仍依赖 UIA，尚非 UIA 完全不可用时的替代方案。

用户可在运行后隐藏分身画面，等待自然新消息再回来比较帧数、变化次数、文字和画面；这项后台截图实测尚未通过。黑屏/纯色帧被拒绝，三次连续失败停止；静止画面与冻结画面不能自动区分。只截取当前绑定窗口，绝不回退到主机屏幕抓取或抢焦点。单次截图及 OCR 在独立进程中最多25秒，下一次间隔3秒，停止后丢弃迟到结果。

OCR 块不是消息，也不自动触发图库指令。本次仅验证混合识别入口，图片原文件获取、发送者身份与真实加图取图闭环仍未接通。依赖可通过项目 vision extra 安装；本机运行环境已安装。参考：[RapidOCR API](https://rapidai.github.io/RapidOCRDocs/v1.4.4/install_usage/api/RapidOCR/)；[PrintWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow)。

只读监听现在读取当前配置群的消息行，识别文字、图片标记和语音行；正文仅保留在运行内存和最近一条 GUI 预览，不写入诊断或日志，不下载图片、不发送。首次启动、发生缺口或重试恢复时以当前列表为基线，不追补历史。计数是连续确认的新增已识别行，不是群消息总数；未知类型、重复身份、列表无法衔接会明确显示。相同正文且不同 AutomationId 可分别计数；UI 身份不等于服务器消息 ID，因此不能保证无损或精确一次。

同一绑定窗口读取失败最多自动重试三次，每次两秒；每次快照仍复核分身窗口和配置群。绑定变化立即停止，不自动改绑主机或其他微信。恢复后显示缺口，不重复派发历史。当前未识别发送者、未接入加图取图处理，也不启用自动发送。真实 4.1.13.12 类型识别与计数需用户验证；模拟测试不代表真实兼容性。

0.6.6 的实际诊断发现三个目标均存在，但整窗遍历触及深度限制。0.6.7 先核对唯一聊天页面，再在页面内搜索；不遍历消息正文和输入编辑器。总节点预算、超时和重复候选拒绝保持不变。回归测试是模拟控件树验证，真实微信监听仍待用户验证；不启用真实发送。

本阶段只读取主窗口结构信息，不读聊天、不监听、不发送，也不调用wxauto。绑定不保存到磁盘；关闭管理器后不保留绑定。检测到窗口关闭、最小化、进程变化、锁屏或检测失败时取消绑定，不会转向其他微信。

## 群内用法

1. A 发送 `/加图 帕姆王`。
2. A 在60秒内另发一条图片消息。B 的图片不会占用 A 的待添加操作。
3. 机器人回复 `已添加「帕姆王」，当前共 1 张。`
4. 任何成员发送 `帕姆王`，机器人随机发一张图。

`/取消` 仅取消本人在当前群的操作；`/帮助` 显示用法。新 `/加图` 替换本人旧操作。中间普通文字不会取消加图。超时后收到图片会提示重新加图；不主动发送超时通知。

匹配仅去掉前后空白，区分大小写，不做子串、模糊或语义匹配。未知普通文字忽略。关键词1～80字符，拒绝路径符号、控制字符和保留命令形式。

相同群、相同关键词按 SHA-256 去重。同图可属于不同关键词或不同群。有两张可用图片时排除上一张成功发送的图片；最后发送记录可跨重启保留。GIF作为图片消息处理，微信表情消息不收录。支持 PNG/JPEG/GIF/WebP/BMP，默认20MB上限、2500万像素上限；格式从内容识别。

## 数据与恢复

```text
data/
  bot.db                 # 关键词、群、上传者、哈希、时间、上次发送
  images/<sha256>.<格式>  # 关键词永不进入路径
  downloads/             # 受控临时下载，处理完成后清理
  .bot.lock              # 系统进程锁，不要在运行时删除
```

图片先写临时文件并刷盘，再原子替换，最后提交数据库。数据库提交失败可能留下无引用完整图片，可重新加图复用；不会提交指向半截文件的记录。异常退出可能留下临时下载，不影响已提交图片。运行中不要手工改数据库或图片。

GUI方案guest默认目录是`%LOCALAPPDATA%\TianyiBot\guest\data`；还包含`bot-config.json`及敏感`management/`证书/密钥。备份：停止机器人和管理服务，复制**整个数据目录**。恢复：保留故障目录，把备份复制到新目录，在guest服务界面选择它，必要时重新配对。不要只备份数据库。待加图状态和短期事件去重不跨重启保存。

图库业务通过 `GalleryService.namespace()` 决定命名空间，未来可改为共享图库；现有群数据需要明确迁移，不会静默合并。

## 已知限制

- 免费后端只提供显示昵称，无法证明不可变微信ID。群成员需使用独特、稳定的显示名；重名会碰撞。无法可靠读到发送者时忽略消息，避免把别人的图加进来。连续消息隐藏昵称可能导致图片被忽略，需要后续真实测试验证。
- 去重使用 `(群名, UI消息ID)`，保留5分钟、最多4096条。UI重建后ID可能改变，跨重启不承诺恰好处理一次；内容哈希不用于消息去重，避免吞掉合法的重复取图。
- 小规模个人群使用；单线程回调保序，下载期间后续事件可能延迟。超时按处理时的单调时钟计算，时间戳为接收时间，并非微信服务器时间。
- 上游监听可能在窗口关闭、最小化、锁屏或客户端升级后失效，不提供后台协议连接或无人值守稳定性保证。
- 上游发送结果用于判断是否成功，进程恰好在发送后退出可能无法更新上次发送记录；不自动重试不确定的发送结果。
- 后端日志已禁用；本项目不记录群消息正文、账号或下载路径。图片/SQLite仍包含群命名空间与上传显示名，应保管好本地数据。
- 已禁用免费库的更新文件清理；图片取图使用已核实的底层UI路径，避开上游保存方法删除源文件的分支。详见集成文档。
